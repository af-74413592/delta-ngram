# 完整多领域训练与旧闻到新闻验证

2026-10-19｜执行计划｜本文件替代旧计划的后续实施顺序

## 1 目标与当前起点

目标是训练能从不同领域的新文本中写入可用记忆的 writer，并检验它在训练之后的新事件上能否利用本次证据回答问题。

目前只完成代码来源的三个小实验：Instruct reader 的 seed17、seed29 各约 5M 目标 token，以及 Base reader 的约 5M 迁移对比。新闻只有两事件的执行小测。**这些是前期基线，不代表多领域训练或新闻泛化已经完成。**

本次直接推进五源混合训练。原生大模型接口、进一步 Base 对比和更换记忆更新算子不作为本次的前置条件。继续使用已验证的冻结 Qwen3-0.6B Instruct reader、外置 n-gram 状态与 D1 writer；训练更新 writer 参数，独立评测只更新在线记忆状态。

## 2 五类训练数据

比例指实际有损失的目标 token，不是文章数或下载体积。

| 来源 | 固定数据集 | 目标 token 比例 | 原文池准备目标 |
|---|---|---:|---:|
| 代码 | `common-pile/stackv2_edu_filtered` | 20% | 复用已验收的约 20M，保留原有家族切分 |
| 论文 | `common-pile/arxiv_papers_filtered` | 25% | 50M |
| 书籍 | `common-pile/project_gutenberg_filtered` | 20% | 40M |
| 长网页 | `HuggingFaceFW/fineweb-edu`，`sample-10BT` | 15% | 30M |
| 旧新闻 | `vblagoje/cc_news` | 20% | 训练区 50M，开发和保留区另计 |

合计准备约 190M 原文 token。实际可用量必须由构建结果确认；未达到目标时记录具体缺口和各采样单元的可用量，不能把下载完成写成训练完成。复用代码的目的包括保留与既有基线兼容的分组；不得为凑新比例重新切分，造成原训练样本进入新开发集。

四个原数据源 revision 沿用[原计划的数据清单](training_plan_20261019.md#2-数据来源与可用量)。新闻固定为 `81eb2ce0d2a9dad6ad16b68ef750ec290880fa36`，详见[新闻来源说明](news_training_source_20261019.md)。每个实际下载分片记录上游 SHA256、大小和版本；仅在有界候选池中进行文档与作品分组，明确近重复检测的范围与遗漏风险。

### 2.1 时间与家族隔离

- 新闻训练：发布日期为 2017-01-01 至 2018-12-31。
- 新闻原文开发：2019-01-01 至 2019-06-30。
- 新闻原文保留：2019-07-01 至 2019-12-31，只在选定 checkpoint 后使用。
- 新近事件问答开发：优先采用 2025 年下半年实际发生的新事件。
- 新近事件最终测试：预定采用 2026 年发生的独立事件，收集前核对所有训练来源已固定版本的存在时间及所选材料的日期上界；不满足“晚于训练材料”条件的事件排除或另标为普通留出。

CC-News 日期来自数据集提取元数据，不能代替每篇原站的人工核验。新闻同 URL、正文重复、确认的近重复和相关标题家族跨时间分区时整组排除。混合时还检查跨来源的同 URL 和正文家族，防止网页来源把新闻留出文本带回训练。普通词面聚类不能证明所有语义事件都已隔离，因此近期问答另外人工核查事件家族与证据时序。

代码按仓库与近重复家族；论文按原始论文及版本；书籍按作品与确认的重复版本；网页按来源 URL 与重复家族分组。最终合并保持既有 split，跨 split 的冲突家族整体隔离。保留集单独保存，不进入 trainer 文件。

### 2.2 新闻短篇的处理

新闻不能继续套用所有文档至少 4,096/8,192 token 的旧配方。固定新闻来源一个 1,000 篇行组的实际抽样中，中位长度为 453 token；达到 1,024、2,048、4,096 token 的比例分别为 15.5%、1.4%、0.5%。这是一个非随机行组的分布检查，不推定为全库比例。

本轮保留 512-token 块与 128-token 局部 prefix，新闻训练使用 **2 块 / 4 块，目标 token 比例 90% / 10%**；其他四源继续 **8 块 / 16 块各半**。完整文章编码一次；只抽取完整轨迹，保存未使用尾部，不拼接无关新闻。

这仍是**长新闻子集训练**，不是覆盖全部短新闻。构建报告必须列出实际长度分布与筛选比例，近期问答评测应包含普通短新闻，以检验训练到短篇推理的迁移。更短块训练属于后续单独配方，不在本次训练途中更换。

### 2.3 数据就绪门槛

1. 五个来源训练、开发、保留区各至少 64 个独立分组；不足即补采或明确失败。
2. 每个实际配置的来源与长度单元非空，报告独立分组数、可用损失 token 与完整窗口数。
3. 固定 100M 预算下，每个训练单元预计消费不超过可用窗口目标 token 的 **3 倍**。这是预先登记的重复消费上限；跨长度复用同一原文另行报告。
4. tokenizer、正文与 token hash、来源版本、split、家族与时间切分检查通过。
5. 合并完成后冻结数据 manifest 和文件 SHA，训练过程中不补入新文档或移动 split。

## 3 M1：五源混合主训练

执行配置：[m1_five_source_seed17.yaml](../configs/m1_five_source_seed17.yaml)。

| 项目 | 预定设置 |
|---|---|
| Reader | `Qwen/Qwen3-0.6B`，revision `c1899de289a04d12100db370d81485cdf75e47ca`，冻结 |
| Writer | 复用 P1 的**第零步随机初始化**；不从已经训练的代码 writer 继续，不恢复旧优化器 |
| 更新方法 | D1，完整轨迹 BPTT，块间先预测后写入 |
| 配比 | 代码/论文/书籍/网页/旧闻 = 20/25/20/15/20 |
| 采样 | 按来源与长度的联合目标 token 配额，精确记录各单元消费 |
| 批量 | 每 microbatch 4 条轨迹，梯度累积 3 次，按有效目标 token 总数归一化 |
| 优化器 | AdamW，学习率 0.0003，weight decay 0，梯度裁剪 1 |
| 总上限 | 100M 有损失目标 token；不足完整轨迹的尾部单列 |
| 保存 | 每约 1M 保存恢复点；每 5M 另存不可覆盖的 writer 与训练快照 |
| 开发评测 | 第零步及每 5M，固定最多 640 个窗口，每来源至少 64 个独立组 |

新闻短轨迹增加了每单位目标 token 的轨迹数，因此累积 3 次后平均约 22.7k 目标 token/step；实际值逐步记录。该配方与旧代码训练的比较是**整体训练配方比较**，不能将收益完全归因于数据多样性。

100M 是本次主 run 的累计硬上限，不因恢复、失败重启或改名重新计数。不因某来源早期收益暂时为负就反复调配比寻找显著；只在非有限 loss/梯度、数据身份变化、状态隔离错误、超出预算或资源故障时停止并修复。超过一次完整轨迹的预算残余或异常退出必须显式报告。

旧代码真实运行约 22 分钟完成 5M，旧配方端到端估计 100M 约 7.3 小时。新混合配方与逐源评测会改变耗时；实际开始后按新训练日志重新估算，不能复用合成输入的吞吐报价。

## 4 比较、开发选择与最终测试

### 4.1 固定比较对象

- P1 seed17 的代码 5M writer：现有基线。
- M1 5M writer：同目标 token 预算的多源配方比较。
- M1 25M、50M、100M：观察完整训练过程；与旧 5M 的差异同时包含训练量变化。

固定开发集上逐来源报告 `self / empty` 的 NLL 和组级配对 95% CI，另报等来源平均 `Δ_empty`。某个来源负收益不得被总体加权平均掩盖。各来源的长短层分别标注样本量，不把 64 个来源分组解释成每个长度层都有 64 个分组。

25M、50M、100M 另做固定 `donor / context` 内容利用诊断；近期新闻开发同时记录候选答案 NLL、候选排序正确率和自由生成正确率。候选选择准确率不能冒称自由生成问答准确率。

主 checkpoint 在预定 5M 间隔候选中，按固定开发集的**等来源平均 `Δ_empty` 最大值**选择；若相同取更早的 checkpoint。100M 终点始终报告。选择过程不使用任何保留集或最终近期事件测试结果。

### 4.2 新闻验证应回答的问题

1. **旧闻到新事件：**在旧闻上训练的固定 writer，读取未见新事件后是否改善回答？
2. **证据依赖：**self 是否同时优于 empty 和来自其他事件的 donor？
3. **修订：**后到达的更正能否替换旧值，减少旧答案？
4. **随机绑定：**在候选词汇保持相同的 A/B 事实交换下，预测是否随在线状态改变？
5. **保持：**插入无关新闻、增长历史后，先前事实的回答是否仍然有效？

近期事件开发和最终测试各以至少 64 个独立事件家族、每家族至少 4 个核查问题为准备目标。证据、查询和标签分开；问题与答案不得写入记忆；self/empty/donor 使用相同查询前缀。context 只作为同一证据的可用性参照。统计按事件家族聚类，而非把每个问题当作独立样本。

真实新事件、真实更正、人工事实交换分别报告，不能混成“新闻准确率”。模型权重在某天已存在，只能给出时间证据；其预训练截止日期未知时继续明确写“未知”。两事件旧样例只用于工程回归，不进入正式泛化结论。

近期事件最终清单、采样规则和证据 hash 在 checkpoint 选择之前冻结，最终测试只在选定 checkpoint 上正式执行一次。结果为负或不确定也构成实验结果，不反复查看最终集来调训练。

## 5 后续阶段及完成标准

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| 数据准备 | 五源构建、时间与家族切分、重复预算审计 | 五源 manifest 就绪且训练前门槛通过 |
| M1 混合训练 | 同一初始化，至多 100M 累计目标 token | 五源实际消费、各预定 checkpoint 与逐源评测均有产物 |
| 新事件验证 | 冻结参数的时间留出、修订、绑定和保持测试 | 固定开发与独立最终测试产物完整，明确通过/未通过/证据不足 |
| M2 对话适配 | OpenAssistant/oasst2 对话支路与等预算 raw 支路 | 各最多 1M，遵守原计划 user-only 写入与 assistant-only loss；通过部署回归才采用 |
| 原生接口与扩展 | 回到原计划 P3/P6 的独立模型与接口预算 | 不把小模型结果当成原生大模型结果 |

“完整多领域训练完成”至少要求 M1 和独立最终验证均完成；“对话部署版本完成”还要求 M2。达到预算和效果达标是两件事：任一领域失败都如实保留，不因执行完成而宣布泛化成功。
