# 完整多领域训练与旧闻到新闻验证

2026-10-19｜执行计划｜本文件替代旧计划的后续实施顺序

## 1 目标与当前起点

目标是训练能从不同领域的新文本中写入可用记忆的 writer，并检验它在训练之后的新事件上能否利用本次证据回答问题。

**2026-10-19 修订：完整能力仅指参数固定后的前向记忆能力。**离线训练 writer 可以使用反向传播；测试时 reader/writer 参数均固定，在线只能前向写入和读取记忆状态。对新事件、后续报道或答案进行梯度优化得到的效果不计入主结果。目标监督的容量 oracle 仅诊断接口，不参与 checkpoint 选择，也不能替代前向能力证据。

目前只完成代码来源的三个小实验：Instruct reader 的 seed17、seed29 各约 5M 目标 token，以及 Base reader 的约 5M 迁移对比。新闻只有两事件的执行小测。**这些是前期基线，不代表多领域训练或新闻泛化已经完成。**

本次直接推进五源混合训练。原生大模型接口、进一步 Base 对比和更换记忆更新算子不作为本次的前置条件。继续使用已验证的冻结 Qwen3-0.6B Instruct reader、外置 n-gram 状态与 D1 writer；训练更新 writer 参数，独立评测只更新在线记忆状态。

### 2.1 时间与家族隔离

- 新闻训练：发布日期为 2017-01-01 至 2017-12-31。
- 新闻原文开发：2018-01-01 至 2018-04-30。
- 新闻原文保留：2018-05-01 至 2018-07-31，只在选定 checkpoint 后使用。
- 新近事件问答开发：优先采用 2025 年下半年实际发生的新事件。
- 新近事件最终测试：预定采用 2026 年发生的独立事件，收集前核对所有训练来源已固定版本的存在时间及所选材料的日期上界；不满足“晚于训练材料”条件的事件排除或另标为普通留出。

CC-News 日期来自数据集提取元数据，不能代替每篇原站的人工核验。新闻同 URL、正文重复、确认的近重复和相关标题家族跨时间分区时整组排除。混合时还检查跨来源的同 URL 和正文家族，防止网页来源把新闻留出文本带回训练。普通词面聚类不能证明所有语义事件都已隔离，因此近期问答另外人工核查事件家族与证据时序。

上述时间窗取代失败的2019年开发/保留方案。[全量原始日期审计](news_date_audit_20261019.json)覆盖708,241条：630,643条日期有效、77,598条缺失，两套解析器按月分布完全一致，没有非空日期解析失败。2019年仅2条，2018年8–12月共9条。新训练/开发/保留窗分别有359,647 / 160,399 / 110,586条原始有效日期记录；实际训练仍须经过正文、长度和跨区家族隔离。旧闻开发与保留池各准备5M原文token，以支持单篇和报道流的独立家族数量。新信息主张仍由2025/2026年独立新事件测试承担。

代码按仓库与近重复家族；论文按原始论文及版本；书籍按作品与确认的重复版本；网页按来源 URL 与重复家族分组。最终合并保持既有 split，跨 split 的冲突家族整体隔离。保留集单独保存，不进入 trainer 文件。

### 2.2 新闻短篇的处理

新闻不能继续套用所有文档至少 4,096/8,192 token 的旧配方。固定新闻来源一个 1,000 篇行组的实际抽样中，中位长度为 453 token；达到 1,024、2,048、4,096 token 的比例分别为 15.5%、1.4%、0.5%。这是一个非随机行组的分布检查，不推定为全库比例。

本轮保留 512-token 块与 128-token 局部 prefix，单篇新闻训练使用 **2 块 / 4 块，目标 token 比例 90% / 10%**；其他四源继续 **8 块 / 16 块各半**。完整文章编码一次；只抽取完整轨迹，保存未使用尾部，不拼接无关新闻。

这仍是**长新闻子集训练**，不是覆盖全部短新闻。构建报告必须列出实际长度分布与筛选比例，近期问答评测应包含普通短新闻，以检验训练到短篇推理的迁移。更短块训练属于后续单独配方，不在本次训练途中更换。

### 2.3 跨文章报道流：保留后续和更正

原标题、URL 和近似正文用于分组与 split 隔离，不能直接作为删除后续报道的理由。新增独立报道流构建器，从已校验原始分片恢复同家族成员，**仅删除规范化正文完全相同的副本**，保守保留事实可能变化的近似稿。

- 每流包含 2–4 篇完整报道，跨度不超过 30 天，按可验证的发布时间排序；无法确定先后顺序的同日报道不组成有序对。
- 首篇全文只写入；后续文章各块先计算预测损失，再写入。整条流共享记忆与离线训练梯度；不同流的记忆相互隔离。
- 每篇文章重置局部文本前缀与 n-gram 边界，记忆状态保持。短块填充不计入损失，也不写入记忆。
- 自动标题/URL 家族只称“自动报道家族”，不能冒称已人工确认的同事件修订。真实更正的验证使用另行核查的事件集。
- 新闻总份额仍为 20%；经下方容量登记，冻结单篇 17.5% 与报道流 2.5%，各单元满足不超过 3 次重复消费的门槛。原 15%/5% 提案及其容量失败记录保留，后续不得静默调整配比。
- 被选作报道流的整个家族从单篇新闻子集移除；移除后单篇与报道流各自仍须通过 split、独立分组数量与容量审计。
- 原单篇来源代表筛选造成的长文偏差、无法恢复的语义关联、流内文章数/实际写入块数/目标 token 分布全部记录。

### 2.4 数据就绪门槛

1. 五个来源训练、开发、保留区各至少 64 个独立分组；不足即补采或明确失败。
2. 每个实际配置的来源与长度单元非空，报告独立分组数、可用损失 token 与完整窗口数。
3. 固定 100M 预算下，每个训练单元预计消费不超过可用窗口目标 token 的 **3 倍**。这是预先登记的重复消费上限；跨长度复用同一原文另行报告。
4. tokenizer、正文与 token hash、来源版本、split、家族与时间切分检查通过。
5. 合并完成后冻结数据 manifest 和文件 SHA，训练过程中不补入新文档或移动 split。

容量登记（2026-10-19，模型评测前）：联合审计保留713个训练事件，后续文章独立目标共991,843 token。原5%报道流份额需要5.041遍，未通过至多3遍门槛；保留该失败审计，冻结报道流为2.5%（2.521遍），普通新闻为17.5%，新闻合计仍为20%。事件4/8/16/32块桶的目标容量分别为95,509 / 655,172 / 201,695 / 39,467，按这些容量比例分配事件预算。新输出使用 `merged_event_v5`，就绪、donor覆盖及完整采样复核通过后才启动训练；配置为 `configs/m1_event_mixture_seed17.yaml`。

单篇短新闻增加每单位目标 token 的轨迹数，报道流又增加可变长度的纯写入历史；加入报道流后按冻结采样计划重新计算每step的目标token和写入量。该配方与旧代码训练的比较是**整体训练配方比较**，不能将收益完全归因于数据多样性。

100M 是本次主 run 的累计硬上限，不因恢复、失败重启或改名重新计数。不因某来源早期收益暂时为负就反复调配比寻找显著；只在非有限 loss/梯度、数据身份变化、状态隔离错误、超出预算或资源故障时停止并修复。超过一次完整轨迹的预算残余或异常退出必须显式报告。

旧代码真实运行约 22 分钟完成 5M，旧配方端到端估计 100M 约 7.3 小时。新混合配方与逐源评测会改变耗时；实际开始后按新训练日志重新估算，不能复用合成输入的吞吐报价。

## 4 比较、开发选择与最终测试

### 4.1 固定比较对象

- P1 seed17 的代码 5M writer：现有基线。
- M1 5M writer：同目标 token 预算的多源配方比较。
- M1 25M、50M、100M：观察完整训练过程；与旧 5M 的差异同时包含训练量变化。

固定开发集上逐来源报告 `self / empty / donor` 的 NLL、`Δ_empty = NLL_empty − NLL_self`、`Δ_donor = NLL_donor − NLL_self` 和家族级配对 95% CI。donor 在第零步及**每个 5M 检查点**都执行；同来源、匹配历史长度、不同家族，配对和 hash 在训练前冻结，不因结果变化重新配对。三个条件的目标 token 与局部查询前缀完全一致。

历史报道流在同一批 checkpoint 上另报 `later_article_first_block`：每篇后续文章第一块的 self/empty/donor，当前文章尚未有任何 token 写入 memory。保留两种口径：全部第一块真实 token（本地 BOS/EOS）；给定该文前128 token后，第一块剩余真实 token（无BOS），后者与新事件续写口径对齐。按事件家族汇总置信区间，记录文章数和实际目标数；这个诊断不替换已冻结的主 checkpoint 选择规则。

单篇新闻和报道流分别报告，再归入同一“新闻”来源计算五来源等权宏平均；新闻内部按固定开发目标 token 加权，不能把两个子集当成两个领域加大新闻的权重。某来源负收益必须单列。25M、50M、100M 另做 context 可用性与写入机制诊断。donor 增加读取前向和供体写入成本，实际耗时单列，不能预设它没有额外写入成本。

主 checkpoint 在预定 5M 间隔候选中，以**五来源等权平均 `Δ_donor` 最大值**选择，且 `Δ_donor` 与 `Δ_empty` 的宏平均家族级配对 CI 下界均须大于零；每个来源至少64独立家族。并列取更早 checkpoint。若没有候选满足门槛，结论是没有合格 checkpoint；100M 终点及全部候选仍报告，不能用纯通用偏置收益替代内容收益。选择过程不使用保留集、近期最终集或任何 target-supervised oracle。

### 4.2 新闻验证应回答的问题

1. **旧闻到新事件，先测续报：**读取新事件早先报道后，能否降低真实后续报道的预测损失？对相同后续 token 比较 self/empty/donor，参数固定，整篇后续报道始终不得写入 memory（包含作为查询前缀的部分）。
2. **问答迁移：**在上述同目标测试之外，报告候选答案 NLL、候选排序准确率和自由生成准确率；三者分别命名，不能把候选选择冒称自由生成。
3. **证据依赖：**self 是否同时优于 empty 和来自其他事件的 donor？
4. **修订：**后到达的更正能否替换旧值，减少旧答案？
5. **随机绑定：**在候选词汇保持相同的 A/B 事实交换下，预测是否随在线状态改变？
6. **保持：**分别报告插入 0/1/4/8/16 篇无关新闻后的续报和问答结果，同时列实际写入块数、token 数与独立事件数。单篇短新闻只有1–3次写入，长流能力主要来自其他领域，必须检验向新闻更多次写入的迁移。

续报子集使用真实先后报道，记录全文或片段范围、发布时间、原文与 token hash；不把自行改写的摘要当真实续报。先完成至少16事件对的工程验证，正式主结论目标为至少64独立事件对；不足时保留样本量和不确定性，不把小测视为完整泛化证据。问答作为第二层，避免单凭问答失败就认定没有形成可用记忆。

**在查看结果之前登记的方向控制：** `self-perm / donor-perm` 对整份 memory 使用共享 width 维通道置换，只改变读取值方向；地址、计数、每行范数及原写入轨迹不变。同一置换用于所有事件、所有干扰距离和self/donor，固定 seed 17/29/43，算法 `random.Random(seed).shuffle(list(range(width)))`，完整映射和 SHA 随评测登记。事件内先平均三个seed作为主方向指标，另报各seed，不择优。原memory继续写，置换view只读。

每个新事件预先人工核验较晚报道前128 token是否已经复述较早报道的关键事实，记录关键事实和原文/导语字符span及hash；按 `restated / not_restated / unknown` 分组报告相同条件和保留曲线，不能根据模型效果调整标注。新事件DEV与FINAL正式续写分别以至少64事件为门槛，QA64不抵正文续写64。修订子集另标同一属性的旧值、新值及原文span，明确修正和状态变化分开统计。

近期事件开发和最终测试各以至少 64 个独立事件家族、每家族至少 4 个核查问题为准备目标。证据、查询和标签分开；问题与答案不得写入记忆；self/empty/donor 使用相同查询前缀。context 只作为同一证据的可用性参照。统计按事件家族聚类，而非把每个问题当作独立样本。

真实新事件、真实更正、人工事实交换分别报告，不能混成“新闻准确率”。模型权重在某天已存在，只能给出时间证据；其预训练截止日期未知时继续明确写“未知”。两事件旧样例只用于工程回归，不进入正式泛化结论。

近期事件最终清单、采样规则和证据 hash 在 checkpoint 选择之前冻结，最终测试只在选定 checkpoint 上正式执行一次。结果为负或不确定也构成实验结果，不反复查看最终集来调训练。

### 5.1 α遗忘消融（不阻塞M1）

在D1上只对补丁Δ做惰性衰减，T0及主干不动。记录每行最后写入的块号；固定/学习全局α在读写时用α的间隔块数次幂，证据决定的变化α用期间各块α的连乘（以累计log实现）。独立事件时钟仅由有效证据块推进；padding和query读取不推进。写入先衰减被触及行再执行原D1，同块多事件共用快照，计数语义保持。

剪枝首先是评估时的只读压缩快照，原状态和写入轨迹不变；不能将丢失计数的快照声称为可精确继续写入的恢复点。另报保持继续写语义所需全部计数/时钟的元数据成本，不把只读文件缩小当作已经实现在线显存下降。
