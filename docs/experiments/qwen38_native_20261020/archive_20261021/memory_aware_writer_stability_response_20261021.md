# 回应：带记忆编码写入器的稳定性推导与试验方案

2026-10-21｜Codex 审阅回应

审阅对象：[《带记忆编码的写入器：稳定性推导与试验方案》](memory_aware_writer_stability_20261021.md)。本回应结合原生 writer、D1、训练调度、检查点保存和 DEV64 实现核对；未运行新的 GPU 试验，本文没有该方案的实测 G。

## 0. 总结

**接受研究方向：写入器并非只能使用固定 T⁰ 编码。整体微调与残差写入器都可以做成有效的探索性试验。**

但当前文稿把“状态有界”“收敛到唯一不动点”“训练梯度稳定”混在了一起，需要分别论证：

1. **固定且有限的参数下，D1 的逐行有界性成立。** 这不等于训练期间存在统一上界，也不保证浮点运算永不出现 NaN。
2. **固定 T⁰ 编码保留了证据目标锚定，但实际门控仍依赖记忆。** 唯一不动点与几何收敛只在额外条件下成立。
3. **当前单方向 g 和 base→mem 的 G 不能认证收缩，也不能推导“g>1 必然锁死”。** 建议将 G 定位为编码替换敏感度，并补充完整更新映射的扰动诊断。
4. **对 H_mem 截断梯度是合理的首轮工程选择，不是数学必需。** 不截断仍是一阶反向传播；截断也不改变前向动力学。
5. **80M 检查点的保存格式支持完整续训。** 未来分叉应复用主线相同的完整轨迹组，并单独登记编码协议、预算及评测变化。

## 1. 接受：固定参数下的状态有界性

原稿 §2 的凸组合证明方向正确。假设：

- writer 参数、头嵌入和目标尺度均固定且有限；
- RMSNorm 的 ε>0，输入及中间计算保持有限；
- 窗口均值和 pool 的权重非负、和为 1；
- β∈[0,1]，α∈[0,1]。

归一化后的单 token 特征范数有界，有限维特征上的连续 writer 因而存在目标上界 Vθ。D1 给出

$$
\|\Delta_j^+\|\le(1-w_j)\|\Delta_j\|+w_j V_\theta
\le\max(\|\Delta_j\|,V_\theta).
$$

从零状态出发，固定 writer 下各行始终有界。该结论不要求编码与记忆无关，因此也覆盖 H_mem。

需要收窄两处表述：

- **训练时 θ 在变。** 若要声称整个训练过程有同一个上界，还需对各步目标给出统一界；当前证明没有提供它。
- **ρ 是初始化校准尺度，不是硬限幅。** 原生实现按初始目标 RMS 校准 `target_scale`，不能把它直接写成恒等式 `s_h = ρ·RMS(T⁰_h)`，也不能据此保证训练后目标仍只有 T⁰ 的 1%。见[尺度校准](../../../../src/delta_ngram/qwen38_native.py#L197)。

建议将“带记忆编码不会让状态爆掉”改为：“固定有限参数并保持有限数值运算时，带记忆编码不破坏 D1 的逐行有界性；收敛性和训练稳定性需另行判断。”

## 2. 修正：固定编码仍有门控反馈

### 2.1 目标核对通过，但加权目标依赖记忆

当前 base 路径的单事件目标 v_a 只读 H、窗口/pool 特征以及阶/头嵌入；旧 Δ、v_a−Δ_old 和计数进入门控。这一点与原稿一致。见[目标构造](../../../../src/delta_ngram/qwen38_writer.py#L119)和[状态门控](../../../../src/delta_ngram/qwen38_writer.py#L141)。

但固定 v_a 并不意味着固定加权目标：

$$
\bar v(\Delta)=\frac{\sum_a\beta_a(\Delta)v_a}{\sum_a\beta_a(\Delta)}.
$$

因此，“状态落在证据目标及零点的凸包内”可以保留；“同一证据反复写时不动点唯一”不能无条件保留。原稿 §3 正文注明了“β 固定时”，结论页也必须保留这个前提。

一个一维反例是 v₊=1、v₋=−1、β₊=σ(4d)、β₋=σ(−4d)。此时 n=2、w=1/2，且

$$
F(d)=\tfrac12d+\tfrac12\tanh(2d).
$$

目标固定、没有带记忆编码，但已有零点和两个非零不动点。这是满足所述数学条件的构造反例，不是当前原生模型的实测结果。它说明“目标固定 + 凸组合”不足以推出唯一性。实际计数还会随写入递增，此时更新是随时间变化的映射，需要额外处理。

若目标和 β 都固定、w 为固定正数，原稿的几何收敛结论成立。若只保证每步 w_t>0，则还不够；固定目标的误差是否消失取决于乘积 ∏(1−w_t)，例如 Σw_t=∞ 是常用充分条件。

### 2.2 §4 的 J 漏掉直接门控重加权

令 B=Σβ_a，D 表示对完整记忆状态求导，并在单步求导时固定证据、计数及事件分组。正确表达式为

$$
D\bar v
=\sum_a\frac{\beta_a}{B}Dv_a
+\frac1B\sum_a(v_a-\bar v)(\nabla\beta_a)^\top.
$$

第二项在 H_base 固定时也可能非零。原稿把 J 全部写成经 H 的链式导数，遗漏了门控直接读取旧 Δ 的路径。

在不动点处，外层 `(bar v−Δ)∇wᵀ` 消失，但上式的内部重加权项不会随之消失。所以不能写成“不动点处局部稳定只看新增编码增益”。

对于被写入的第 j 行，完整单步导数可写为

$$
DF_j=(1-w_j)P_j+
\frac1{n_j}\sum_{a\to j}
\left[\beta_a Dv_a+(v_a-\Delta_j)(\nabla\beta_a)^\top\right],
$$

其中 P_j 从完整状态中取出第 j 行。H_mem 会引入跨行耦合，不能只检查每行自己的输入扰动。α=1 时未写入行保持恒等，也意味着“整个状态空间单步严格收缩”通常不是合适的直接要求。

## 3. 修正：g 与 G 的判读

### 3.1 范数没有反馈方向，也不覆盖其他方向

原稿用 g=‖Ju‖/‖u‖，再把 `(1−w)+wg` 当成放大倍数。这通常至多是忽略其他项后，由三角不等式得到的上界；只有特定方向关系下才会取等。

- **某方向 g<1 不代表所有方向收缩。** 例如 J=diag(0.5,2)，第一方向的 g 小于 1，第二方向仍可能扩张。
- **g>1 不代表正反馈或多个不动点。** 取 w=0.25、bar v(d)=−tanh(2d)，原点 g=2，但 F′(d)=0.75−0.5 sech²(2d) 始终在 [0.25,0.75] 内，仍是全局收缩。

固定证据和计数、映射可微时，完整 DF 在不动点处的谱半径小于 1，是局部渐近稳定的充分条件。全局唯一性及原稿的偏移界，需要在相关不变域上成立的统一 Lipschitz 条件，不能用某个方向或样本分位数代替。

实际轨迹中的证据、计数和写入行都在变化。即使若干单步局部量看起来正常，状态误差也可能通过不同方向和跨行耦合累积，应观察完整扰动轨迹。

### 3.2 原稿 G 可以保留，但应改名并降低结论强度

现有比较固定直接输入 writer 的旧 Δ，只把 H_base 换成 H_mem，测到的是“编码替换敏感度”。它不是完整 F 在当前状态附近的导数，也不是把完整状态从 0 变成 Δ 的总效应。

即使是真正的 0→Δ 割线，也不能保证局部稳定。例如 bar v(d)=0.5+0.25 sin(4πd)，在不动点 d=0.5 有 bar v(0.5)=bar v(0)，割线增益为 0，但该点导数为 π；w=0.5 时完整更新在该点扩张。

建议修改：

1. 将 G 称为“编码替换敏感度”，保留中位数、p99 和分组统计。
2. 将原行级 g_j 称为“第 j 行输出敏感度”；同时扰动所有读入行时，不能称为该行自环。
3. 对接近零的分母规定过滤阈值，并报告过滤比例。
4. 删除“p99<1 即可认定稳定”。“p99>1 停止”可以是预先登记的保守操作规则，但应注明它不是失稳定理，并明确检查频率。
5. 不能从平均 loss 变化约 0.05 nat 推出 g≪1。λ 与增益近似线性也仅是平滑、局部且路由不变条件下的近似。

### 3.3 建议补充的诊断

- 在实际 Δ 附近，对完整更新 F 做 ±εu 扰动，覆盖多个 ε、随机方向及结构化行扰动。
- 同时重新计算 H、目标和门控，纳入所有跨行影响。
- 固定证据、计数、BOS、prefix、mask、batch/lane、padding 和 RNG；报告重复运行误差与路由翻转。
- 从两份邻近状态开始，沿相同证据轨迹运行，观察误差随块数的变化，并单列修订任务表现。

这些仍是有限样本诊断，不构成全局稳定证明。主线100M可测，实际分叉起点80M也应测。

## 4. 修正：stop-gradient 的作用

建议首轮继续采用 detached H_mem，但把 §5 的理由改为计算和优化上的取舍。

冻结 reader 参数后，对输入 Δ 求梯度仍是普通一阶链式求导。只有继续对“梯度本身”求导，才涉及二阶导数。完整 BPTT 的雅可比连乘可能放大、衰减或稳定，并不必然爆炸。参见 [PyTorch autograd 说明](https://docs.pytorch.org/docs/2.14/notes/autograd.html)和 [Pascanu 等关于 RNN 梯度的分析](https://proceedings.mlr.press/v28/pascanu13.html)。

对 H_mem 截断梯度会删除“旧记忆→编码→writer 特征”这条反向分支，但不改变前向状态轨迹。它是对完整目标梯度的近似，而不是前向稳定措施。保留的直接状态梯度结构与现状相似，但 H、目标、门控及状态都已改变，不能说雅可比数值完全相同。

当前 writer 已对 H 做 detach。实现时可用独立 detached read snapshot 在无梯度模式下编码，再用原有可微状态执行 writer/D1 更新。见[现有 detach](../../../../src/delta_ngram/qwen38_writer.py#L103)和[状态链 VJP](../../../../src/delta_ngram/qwen38_training.py#L515)。

**残差组冻结 base writer 时，只冻结其参数。** 门控读取旧 Δ 的计算和 D1 更新仍需保留 autograd；不能把整个 base writer 更新包进 `no_grad()`。

## 6. 试验实现与比较协议

### 6.1 保留阶段③④，改造前面的编码顺序

现状先批量取得整组证据 H_base，再按轨迹构造写入状态，之后批量做 query 前反向和 writer VJP。H_mem 依赖写入前状态，因此应改成：

`保存 S_t → 用 detached S_t 编码本块 → detach H_mem → 在原有计算图上写入 → 得到 S_(t+1)`

同轨迹未来块不能提前编码；不同轨迹当前已就绪的块仍可批处理。之后阶段③④可以保留。

不能直接把 state 塞给现有 `mode="evidence"`，该模式明确禁止携带 state；有梯度的 state 也不能直接在 `no_grad()` 下 query read。应新增明确的无 CE 编码入口，使用独立 detached snapshot、正确的 query read mask，并在取得 H 后跳过 LM head。见[adapter 约束](../../../../src/delta_ngram/qwen38_adapter.py#L219)。

### 6.2 “免费取得查询 H”只适用于部分事后诊断

现有 query capture 没有 H，需要新增捕获 hook。对于保持旧 base 写入轨迹的事后诊断，可从已有 query 前向取得相应 H；但它不能反过来驱动之前已经构造完毕的 writer history。

此外，当前 event 文章首块的 query 加 BOS，而 evidence 不加；query 的读 mask 包含 prefix，写入 mask 只包含新 token。G 对照必须统一这些输入和 mask，不能直接比较现有 Q4 query H 与 H12 evidence H。见[输入 frame](../../../../src/delta_ngram/qwen38_train_data.py#L187)与[批处理 mask](../../../../src/delta_ngram/qwen38_train_batching.py#L95)。

### 6.3 DEV64 各条件必须沿各自状态编码

- self、donor 分别从空状态开始；H_mem 随各自状态重算。
- 干扰距离 k=0/1/4/8/16 沿各自嵌套前缀继续写入。
- H_base 可以按文章缓存，H_mem 不能跨不同状态直接共享。
- 方向置换只作用于评分时的读视图，不能污染后续编码和写入状态。
- 后来文章的查询窗与早期/干扰文章的写入块不同，已有查询 H 不能直接代替写入 H。
- 额外诊断保存并恢复 RNG，避免改变后续评测或训练流。

现有流程见[DEV64 写入与评分](../../../../scripts/native_qwen38/qwen38_native_dev64_eval.py#L390)。

### 6.4 两组分叉的共同预算

80M 与100M节点按完整组边界截断，实际新增 targets 不一定恰好20M。应登记为“重放主线80→100节点之间相同的完整轨迹组、实际 targets 和更新数”，并保留相同 sampler 起点及学习率安排。

新方案需独立代码版本和恢复迁移记录。当前 runner 校验 code hash 与 policy，不能直接修改正在运行的冻结代码再把它当作普通续训。见[恢复校验](../../../../scripts/native_qwen38/qwen38_native_train_staged_alpha100.py#L286)。

### 6.5 残差组的规模与零初始化

双倍特征宽度为15,424。若共享128维隐层、联合输出160维 δv 和1维 δℓ，则参数为：

`15,424×128 + 128 + 128×161 + 161 = 1,995,169`。

因此“约200万”成立，但需要明确共享隐层。若照现有 target/gate 两塔分别复制，规模接近400万。

第0步代数等价需要输出权重和偏置都为零，并复用原始 gate logits、同一 base 特征和状态。当前 `events()` 只返回 sigmoid 后的 β，不能反求 logit 后再声称严格一致。新增编码调用还应隔离 RNG；批形状改变不能承诺逐位等价。

零初始化使新增编码反馈分支为零，不能写成整个写入映射 g=0，因为原 base 门控仍读取 Δ。容量对照可以在观察到收益后补做，但完成前不应把收益归因于带记忆信息本身。

### 6.6 成本需区分两组

- **整体微调：** H_mem 可替代 H_base 编码，主要额外代价可能是因果串行化和较小批次，不一定每块净增一次编码前向。
- **残差组：** 同时需要 H_base 和 H_mem，通常确实新增编码前向。
- **诊断：** pre-LM-head 的无标签编码新增 GPU 计算，但 CE targets 为0；若调用完整 query/score 后忽略 loss，实际计算过的 CE 仍须单列记账。

建议先按固定协议短测吞吐和显存，再登记正式预算。训练 targets、诊断/评测 CE、编码输入 token 与 GPU 时长应分别记录。

## 7. 建议替换原稿的结论段

> 带记忆编码并不必然破坏 D1 的有界性：固定有限 writer 下，归一化特征和凸组合更新仍给出逐行状态界。固定 T⁰ 编码额外保证单事件目标由证据决定，但门控依赖记忆，所以加权目标和完整状态更新仍有反馈，唯一收敛不能无条件保证。带记忆编码增加了经 H 的反馈路径，其影响需要通过完整更新和长轨迹扰动诊断判断。现有 base→mem 的 G 可作为编码替换敏感度，不能单独认证收缩或预测锁死。首轮试验采用 detached H_mem，以控制计算图成本并保持明确的优化协议；同时分别评估整体微调和零初始化残差写入器的收益、修订能力与运行成本。

**建议结论：保留两组试验设计，先修订理论表述与测量协议，再把实现和预算登记为主线完成后的独立探索性试验。**
