## 正式节点 DEV64

使用既定 64 个事件家族、128 篇配对原文及 18 篇背景原文。准备入口为 `scripts/native_qwen38/qwen38_native_dev64_prepare.py`：从冻结 UTF-8 原文重新使用训练所绑定的 Qwen3.8 tokenizer 编码，输出独立的 `plan.json`、`tokens.json` 与 `COMPLETE.json`。原有事件集合、donor 和干扰文章顺序全部保留，不解码旧 token IDs 恢复正文，也不打开 FINAL 内容。

收益口径沿用全部 64 家族、0/1/4/8/16 篇干扰条件，以及 self、empty、固定 donor 和三个固定 seed 的方向置换。每篇目标文章保留原生 128-token 前缀，之后每窗口最多评分 384 个目标，覆盖所有剩余目标；查询和目标文章均不写入记忆。主指标是按家族等权的 `NLL(empty) − NLL(self)` 与 `NLL(donor) − NLL(self)`，同时报告 pooled token NLL 和首目标窗口收益。

每次完整评测实际 CE 访问为 `41 × 全部后来文章原生目标 token 数`，进入独立的 DEV64 账本，不计入 optimizer 消费，也不冒充此前接口诊断消费。原生前缀重新登记：仅在旧正例 span 仍完整位于新前缀内，或新前缀为旧负例前缀的子集时继承标签；其他记为 `unknown`，不直接套用旧 tokenizer 的 34/30 分组。主收益覆盖全部 64 家族，不按这些标签筛选。

CPU 原生派生已完成；该准备过程未调用 reader、未消费 CE。全部 64 家族每个干扰距离共 **53,593** 个目标 token，每次完整 DEV64 评测计 **2,197,313** 次目标访问。新前缀为 **34 restated / 23 not_restated / 7 unknown**。部署数据位于运行根目录的 `data/native_dev64`；`COMPLETE.json` SHA256 为 `2c28fe875fc00cd1fda528e8a66c1cbb7443f205cab9d42fc13d40851280a453`，plan 与 token 文件身份完整登记于采用 JSON。main05/06只保存了4/64家族partial；main07现已保存完整64家族report与COMPLETE。

## 实现范围

每组仍包含 12 条完整轨迹，采用 TP1/PP1/EP4/ETP1/DP4/CP1：

1. 对本组证据帧计算冻结 reader 的 base-only H，暂存 CPU；跳过不会被使用的词表输出头。
2. 沿每条轨迹的时间顺序运行原 D1 writer，在每次查询前保留不可变记忆快照。
3. 跨时间组成查询微批。每个 `(轨迹, 查询时刻)` 使用独立地址空间，读取侧叶子的梯度送回原快照。
4. 对各轨迹执行完整 writer VJP；全组梯度在四卡间 SUM，一次裁剪、一次 AdamW 更新。

所有查询均除以实际全组目标数一次。BPTT 不截断，不提前写入未来证据，writer 参数在组内保持固定。释放查询叶子后，仍保留原 writer 计算图与相应 cotangent。读取侧激活受微批大小控制；writer 历史与快照的内存仍随轨迹增长，不能宣称总显存与轨迹数无关。

实现文件：

- `src/delta_ngram/qwen38_staged_batching.py`
- `scripts/native_qwen38/qwen38_native_staged_schedule.py`
- `scripts/native_qwen38/qwen38_native_staged_trial.py`

新增 8 项 CPU 测试通过。另用真实 writer、相同 H 与固定 cotangent 对照交错/延后执行：6 个快照逐 bit 相同，writer 梯度相对差异约 4.6e-8。该结果只覆盖 writer 与梯度桥接，不证明原生 reader 数值等价。

每组两种分支均恢复相同 writer、AdamW 和 RNG。下一组共同起点采用参考分支的更新。原模式为 B3 交错执行；候选模式为 H 最大 B12、查询最大 B4。不同 batch 尾部形状会首次编译，因此第二组也不能自动当作热启动结果。

|---|---:|---:|---:|---:|---:|---:|
| 1 | 33,397 | 75.93 | 57.31 | 0.001054 | 0.6061 | 0.8019 |
| 2 | 22,528 | 22.25 | 42.65 | 0.000268 | 0.4692 | 0.8831 |

## 单组原因隔离

另用相同第 48 组、相同初始 writer/AdamW/RNG，分别执行：

- A：原 B3 交错调度，保留 H、快照和读取侧梯度作为内存参照。
- B：精确复用 A 的 H，先构建 writer 历史，再保持原查询波次、B3 同批样本与顺序。
- C：精确复用 A 的 H，再改为跨时间查询 B4。

| 对照 | 有效 Δ 相对 L2 | 读取侧 cotangent 相对 L2 | writer 梯度相对 L2 | writer 梯度余弦 |
|---|---:|---:|---:|---:|
| B 对 A | 6.32e-9 | 0.8598 | 0.5775 | 0.8394 |
| C 对 A | 6.30e-9 | 0.7850 | 0.8528 | 0.7526 |

所有 66 次查询的帧身份、地址和 counts 都一致；Δ 最大绝对差为 7.45e-9。Δ 非逐 bit 相同，不能把 B 当作已经完成的 exact-input reader 重复性测试。B 也失败，说明尚不能把原因归结为大 batch 或新打包函数。读取侧差异已在 writer VJP 之前出现。

首波同 B3、同帧的完整输出头/跳过输出头对照中，H 逐 bit 相同。把证据改为 H12 后，原始 H 相对 L2 差异为 0.1159，RMSNorm 后为 0.1306；所以提前算 H 与改变 H 的 batch 必须分别讨论。

上述试验的 jitter、专家容量上限均为 `None`，attention/hidden dropout 为 0。它们不能解释这次差异。源 checkpoint SHA256 再次核验未变。详见[单组隔离回执](qwen38_native_staged_diagnostic_20261020.json)。

## 完全相同输入的读取侧重复性

固定首个查询波次的 5,632 个目标、相同 B3 帧、相同 RNG、同一个 packed FP32 叶子及其全部字节，使用原查询入口重复计算。第三次先插入同 B3 的 base-only 证据前向，再恢复 RNG。第四次从相同 H 重算 writer，并分配新的读取叶子。四次均无优化器更新。

| 对照 | 逐 token CE / H / 路由 | leaf cotangent 相对 L2 | cotangent 余弦 |
|---|---|---:|---:|
| 原输入立即重复 | 全部逐 bit 相同 | 0.02144 | 0.999773 |
| 插入证据前向后重复原输入 | 全部逐 bit 相同 | 0.01844 | 0.999831 |
| 同 H 重算 Δ，使用新叶子 | 前向和路由改变 | 0.27794 | 0.961014 |

第四次 Δ 最大绝对变化为 1.86e-9、相对 L2 为 4.95e-9；有效位置最终 H 的相对差异为 0.06742，逐目标 CE 相对差异为 0.03187，共 188 个 rank/layer 路由图发生变化。被检查的小 buffer 内容、版本和对象均未改变；强制随机均衡路由关闭。

前三次的前向完全一致，但反向并非逐 bit 可重复，其中一次也略超过预设 0.02 门槛。因此保留原始阈值和失败标志。第四次同时改变了 Δ 数值和叶子分配，单凭此对照不能确认前向差异由数值变化单独引起。已完成的值切换控制见下一节。详见[重复性回执](qwen38_native_reader_repeat_20261020.json)。

## 同叶子值切换控制

固定相同首波 B3 输入、RNG 与读取入口，依次使用原值、同一个叶子写入重算值、同一个叶子恢复原值，以及新叶子装载完全相同的原值。四次均无优化器更新。

| 对照 | Δ 最大绝对变化 | 逐 token CE / 有效 H / 路由 | leaf cotangent 相对 L2 | cotangent 余弦 |
|---|---:|---|---:|---:|
| 同叶子切换为重算 Δ | 1.862645149e-9 | CE 相对 L2 0.03451983；有效 H 相对 L2 0.05429254；188 个 rank/layer 路由图改变 | 0.3155838 | 0.9495638 |
| 同叶子恢复原 Δ | 0 | CE、H、路由全部逐 bit 相同 | 0.01847 | — |
| 新叶子装载原 Δ | 0 | CE、H、路由全部逐 bit 相同 | 0.01826 | — |

该控制支持这次前向及路由变化由 Δ 数值微扰触发，叶子的新分配不是必要条件。恢复原值和更换叶子后的前向均恢复逐 bit 一致，反向仍有约 1.8% 的重复差异。现有结果没有证明这些差异零均值、无害，或新旧调度落在同一噪声分布中。

真实 D1 在 `src/delta_ngram/operators.py` 中通过 `index_add(0, inverse, changes)` 聚合同一 physical row 的 FP32 增量；它是 writer 末位变化的候选来源。独立零 CE CUDA 归约 probe 尚未执行，现已取消执行，因此没有把该行登记为已实测定位的根因。
