## Primary decision: retain the I-trained writer

The Base arm completed 256 optimizer steps and **4,997,632 actual loss tokens**
under the nominal 5M ceiling. Its 2,368-token remainder could not fit another
complete trajectory. No budget extension or second Base seed was used.

The exact P1 step-zero writer tensors, all 256 training batches, dataset bytes,
effective tokenizer, trajectory recipe and actual AdamW parameter groups matched.
The Base arm explicitly used the I tokenizer; the native Base EOS difference and
both original tokenizer identities remain recorded in the preflight artifacts.

Both writers were evaluated using **I evidence encoding and I readout**, on the
same 76 document groups, 111 windows and 463,360 evaluation target tokens.
Every group's empty-memory loss matched the archived I baseline exactly.

| Matched training budget | I-to-I NLL | B-to-I NLL | G = I-to-I minus B-to-I | 95% paired group CI for G |
| --- | ---: | ---: | ---: | --- |
| 0 | Identical | Identical | 0 | [0, 0] |
| 2,502,656 | 1.1424279221 | 1.1668379994 | -0.0244100774 | [-0.0273382010, -0.0215464925] |
| 4,997,632 | 1.1319365565 | 1.1617128572 | -0.0297763008 | [-0.0336457199, -0.0260952650] |

At the final endpoint, B-to-I was worse in all 76 groups. The bootstrap uses
2,000 paired document-group draws, seed 104729, and target-token weighted sums.
The code/data/sample/identity checks and independent arithmetic audit passed.

The transferred Base writer still improved over empty: **0.0065638479**
nat/token, CI **[0.0053991844, 0.0078504212]**. The I-trained writer's improvement
over the same empty reader was **0.0363401487** nat/token. Base's own validation
(Base weights + I tokenizer) improved by **0.0114221828**, CI
**[0.0097544841, 0.0129919390]**; this is a separate trainability diagnostic,
not a comparison on the deployment reader.

These results support keeping I for this seed, budget and code development set.
They do not show that all Base training or subsequent adaptation is ineffective,
and do not identify why cross-reader transfer loses performance.

## First news check: execution passed, no answer-accuracy gain demonstrated

The fixed **P1 I seed17 5M writer** was used, as registered before seeing P2's
outcome. The unchanged manifest contains two sourced development events and four
binary candidate questions. It has no final-holdout events, synthetic swaps,
correction sequence or intervening-write retention probes.

| Condition | Correct candidate answers | Gold answer NLL |
| --- | ---: | ---: |
| Self memory | 0/4 | 2.4537655967 |
| Empty memory | 0/4 | 2.5016070230 |
| Different-event donor | 1/4 | 2.3899075099 |
| Full evidence context | 4/4 | 0.8202296666 |

All conditions scored the same 35 gold-answer tokens. Self, empty and donor had
identical visible question prefixes. Writer state tensors were exactly unchanged;
the reader remained frozen with unchanged parameter versions and no gradients.
Reader contents were not separately hashed in memory. No optimizer was used.

Self slightly lowered gold NLL versus empty without changing candidate accuracy;
donor performed better than self on this tiny fixture. Full context could recover
the answers. The fixture demonstrates successful execution and a gap on these
questions, **not** reliable news-memory generalization or a powered failure claim.
Candidate ranking is not free-generation accuracy; source dates do not certify
pretraining novelty. The original source links are in the
[fixed manifest](../examples/news_dev_smoke_20261019.json).
