# M1 DEV64：原始模型完整上下文参照追加登记

2026-10-20；在本项 GPU 结果产生前登记。用户要求补齐“原文放进上下文”的参照，并明确使用原始权重。本项只增加开发集评测，不改变 100M 主、65M 次的检查点身份，不启动训练或 FINAL。

## 模型与输入

- 使用原始冻结 `Qwen/Qwen3-0.6B`，revision `c1899de289a04d12100db370d81485cdf75e47ca`，与已完成 M1 DEV64 的 reader 相同。使用 BF16、SDPA 和原 tokenizer。
- 直接加载原始因果语言模型；不加载 writer 检查点，不创建或注入记忆，不调整底座权重。
- 使用原冻结 DEV64：registry SHA256 `9ea663ad70131e272522cbad8f6c0fa20bc03f41b324fe7b71d0fb8f4fbfccc2`；prefix annotations SHA256 `7164e9f8b6f23ebfeaaccc2687a6a8b6ad222803f705bacd1a203a2596fdbcce`。
- 64 个事件、干扰文章数 `k = 0, 1, 4, 8, 16`。A、干扰文章和 B 的 token 身份及干扰顺序沿用冻结 registry。

## 评分条件

每个原评分窗口的输入为：

```text
A 全文 + 分隔 + D1 全文 + … + Dk 全文 + 分隔 + B 的原局部评分窗口
```

文章边界使用单独 tokenization 的 `"\n\n"`，固定为 token ID `[271]`。逐篇沿用原 token 序列，避免重新 tokenize 拼接文本改变 B 的目标 token。`k=0` 时只在 A 与 B 之间添加分隔。

B 的局部窗口与原记忆实验完全相同：128 token 的真实左侧前缀，随后最多 384 个评分 token。每个评分 token 只可注意其左侧内容；不给出未来 B，不额外加入此前窗口之外的 B 历史。A 和干扰文章不计入损失。

每个距离覆盖全部 64 个事件、52,914 个目标 token、173 个窗口；五个距离合计 320 个事件条件、865 个窗口。首个评分窗口单独报告。模型实际最大长度为 40,960 token；预检记录每个输入长度，任何超限均报错，不截断。

先用原始模型重算全部 64 个事件的 empty 条件，并与原冻结 empty 逐事件核对，以验证模型、token 和损失口径一致。仅为降低 LM head 的显存占用，可只生成评分所需位置的 logits；必须先通过与完整 logits 路径的对齐测试。

## 统计量与解释

先计算每个事件的目标 token 平均 NLL，再对 64 个事件等权平均。对每个距离：

```text
记忆收益 = mean(NLL_empty − NLL_self)
原文上下文收益 = mean(NLL_empty − NLL_context)
收益比例 = 100 × 记忆收益 / 原文上下文收益
```

使用均值之比，不平均逐事件比率。主要结果使用已登记的 100M writer；65M 与全部 21 点作为次要和曲线诊断，只复用已完成的 writer 结果。上下文模型不依赖 writer 检查点，因此只评测一次。

配对 bootstrap 以 64 个事件为单位，同一次抽样保持 empty、self、context、距离及检查点对应，固定 seed `20261020`，10,000 次，报告 95% 区间。分母均值不为正时不解释百分比；分母区间跨零时标记比例不稳定。不得删除非正分母的抽样来缩窄区间，也不把比率裁剪到 0%–100%。

该百分比表示本协议下恢复的 **NLL 预测收益比例**，不等于事实召回率、答案准确率或理论记忆上限。完整上下文同时包含 A 和干扰文章，因此它不是 A 独有信息贡献的隔离估计。
